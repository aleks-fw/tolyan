# План: сайт «Толян» (аренда грузовиков и доставка стройматериалов)

Папка проекта: `D:\Claude\папа бизнес` (существует, пустая). Всё создаётся и хранится там, на диске C ничего не ставится.
Стек: чистые HTML + CSS + JavaScript, без фреймворков, без npm-зависимостей. Supabase подключается на последнем этапе.

## Context

Нужен рабочий сайт для компании «Толян»: клиент выбирает грузовик или стройматериал, оформляет заказ, получает готовый
текст для Telegram; владелец видит все заказы и управляет каталогом в админ-панели. Заказ обязан сохраняться в базу
независимо от того, написал ли клиент в Telegram. Автоотправки без бота нет, поэтому на первом этапе: копирование текста
и открытие Telegram, с точкой расширения под бота.

## Решения, согласованные с пользователем

- **Данные**: сначала демо-режим на localStorage с тестовыми данными (этапы 1-4), затем Supabase одним слоем (этап 5).
  Ничего внешнего не создаём, пока пользователь не скажет «да».
- **Фото**: бесплатные фото из интернета (Unsplash/Pexels), скачиваются в проект; SVG-заглушка на случай ошибки загрузки.
- Работаем этапами, после каждого этапа остановка и отчёт. Выполняю сам, без субагентов. Локальный `git init` и коммиты
  по этапам; `git push` только по явному «да».

## Модель данных

- **materials**: id, name, description, unit (т / м³ / мешок), price, stock, active, sort, image
- **trucks**: id, name, body (борт/самосвал/манипулятор), capacity_t, price_per_hour, status
  (`available` / `busy` / `service`), image, description, active, sort
- **orders**: id, number (счётчик, показываем «№12»), type (`delivery` / `rental`), status
  (`new` / `confirmed` / `in_progress` / `done` / `cancelled`), customer_name, phone, address, date, time, comment,
  items (jsonb: строки материалов или грузовик + часы), total, message_text, created_at
- **settings** (ключ-значение): company_name, tagline, phone, email, address, work_hours, telegram_username,
  hero_title, hero_subtitle, advantages (4 блока: заголовок + текст), footer_text, delivery_note

Адаптерный интерфейс `store`: `listMaterials/saveMaterial/deleteMaterial`, то же для trucks, `createOrder`,
`listOrders`, `setOrderStatus`, `deleteOrder`, `getSettings/saveSettings`, `exportAll/importAll`, `login/logout/isAdmin`.
Сайт и админка зовут только этот интерфейс, поэтому переход на Supabase не меняет UI.

## Публичная страница (index.html)

Шапка с логотипом «Толян», навигация-якоря, переключатель темы, кнопка «Заказать доставку», бургер на мобильном.
Разделы по порядку:
1. **Hero**: заголовок и описание из настроек, кнопки «Заказать доставку» и «Выбрать машину», фото грузовика.
2. **Преимущества**: 4 карточки (тексты из настроек).
3. **Машины**: карточки с фото, ценой за час, бейджем статуса, кнопкой «Забронировать» (неактивна, если не свободна).
4. **Материалы**: карточки/таблица: цена, единица, остаток, «Заказать» (подставляет материал в форму доставки).
5. **Оформление доставки**: строки «материал + количество» (можно добавить несколько), адрес, дата, имя, телефон,
   комментарий, живой подсчёт итога.
6. **Контакты** и подвал (из настроек).

Бронирование грузовика: модальное окно: часы (1-24), дата, время, адрес подачи, имя, телефон; стоимость = часы × цена за
час пересчитывается на лету; шаг подтверждения со сводкой перед отправкой.

## Заказ и Telegram

1. Форма проходит валидацию (сообщения об ошибках под полем, `aria-live`).
2. `store.createOrder()` сохраняет заказ и возвращает номер. Только после этого показываем окно.
3. Окно «Заказ оформлен»: номер, краткая сводка, текст сообщения (read-only), кнопки:
   - **Скопировать заказ** (`navigator.clipboard`, запасной вариант через `execCommand`);
   - **Открыть Telegram владельца** (`https://t.me/<ник>`);
   - **Отправить заказ в Telegram** (`https://t.me/<ник>?text=<текст>`; текст дополнительно копируется в буфер,
     подсказка «если текст не подставился, вставьте из буфера»; проверяется на этапе 3, префилл для личных чатов
     Telegram держит не везде).
4. Если сохранить не удалось: понятная ошибка, кнопка «Повторить», текст всё равно можно скопировать.
5. Точка расширения: `notifyOwner(order)` в `store.js`, сейчас пустая; в README описано, как подвесить на неё бота
   или Supabase Database Webhook + Edge Function с Telegram Bot API.

Текст сообщения без эмодзи: «Заказ №N, «Толян» / тип / состав с ценами / итого / адрес / дата и время / клиент и
телефон / комментарий». Ник нормализуется (убрать `@` и `t.me/`, проверка `^[A-Za-z0-9_]{5,32}$`).

## Админ-панель (admin.html)

Тот же стиль и переключатель темы. Вход: в демо-режиме пароль из `config.js` (не защита, баннер «данные только в этом
браузере»); в режиме Supabase: Supabase Auth (email + пароль владельца). Вкладки:
- **Заказы и брони**: таблица (№, создан, тип, клиент/телефон, состав, сумма, дата, статус-селект), фильтр по статусу и
  типу, поиск, карточка заказа с текстом и кнопкой копирования, значок количества новых, удаление с подтверждением.
  Сверху три плитки: новые, в работе, сумма выполненных. Без графиков.
- **Материалы**: добавить, изменить, удалить, быстрая правка цены и остатка в строке, переключатель «показывать».
- **Грузовики**: фото (URL или загрузка файла), цена за час, статус доступности, описание.
- **Настройки**: компания, контакты, тексты главной, преимущества, блок Telegram (ник, телефон, email), резервная копия
  (скачать/загрузить JSON, сброс демо-данных).

Все пользовательские строки выводятся через `textContent`/escape (защита от XSS в заказах).

## Дизайн и UX

- Белый фон, тёмный текст, оранжевый акцент (около `#F97316` для заливок; для текста на белом берём темнее,
  чтобы контраст ≥ 4.5:1). Тёмная тема: тёмно-серый фон, тот же оранжевый.
- Тема хранится в `localStorage` (`tolyan-theme`), по умолчанию светлая; общая для сайта и админки.
- Появление блоков через IntersectionObserver, мягкие hover у кнопок и карточек, `prefers-reduced-motion` отключает
  анимации. Шрифт: системный стек или один локальный шрифт, без внешних запросов.
- Адаптив: проверка на 360, 768, 1280 px, без горизонтального скролла.
- На этапе 2 один дизайн-скилл для полировки визуала (design-taste-frontend); больше скиллов и лишних скриншотов не
  запускаю.

## Решения по умолчанию (скажи, если нужно иначе)

- Остаток материала не списывается автоматически, владелец правит его в админке; клиент не может заказать больше
  текущего остатка.
- Занятость грузовика по датам не считается: статус доступности владелец ставит вручную.
- Доставка отдельной строкой в цене не считается; пояснение выводится из настройки `delivery_note`.
- Язык интерфейса только русский; валюта ₽.
- Публикация (GitHub Pages и т.п.) в этот план не входит, обсудим отдельно.

- Адаптив 360 / 768 / 1280, тёмная тема, отсутствие ошибок в консоли, клавиатурная навигация и фокус в модалках.
- На этапе 5: анонимный пользователь не может читать `orders`, заказ через RPC создаётся, владелец после входа его
  видит; сохранение работает при закрытом Telegram.
